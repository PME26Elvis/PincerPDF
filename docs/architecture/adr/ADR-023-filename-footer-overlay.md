# ADR-023: Geometry-matched filename footer overlay

- Status: Accepted for P4.7 partial parity
- Date: 2026-08-03
- Scope: Merge output policy

## Decision

When the Merge request enables `add_filename_footer`, PincerPDF will create a
private overlay PDF with one page for every assembled output page. The overlay
page copies the source page's resolved MediaBox, CropBox and rotation and draws
the contributing source filename near the lower-left media-box origin. Pages
generated by `add_blank_page_if_odd` receive an intentionally empty overlay
page. QPDF applies the overlay before any PincerPDF bookmark reconstruction.

The option crosses the typed Merge engine request, application options, native
desktop DTO and Leptos advanced-safety control. The default remains disabled.

## Rationale

- A separate overlay keeps source page content immutable and preserves the
  existing process-isolated QPDF boundary.
- One overlay page per output page handles reordered and duplicated selections
  without relying on QPDF's repeat-page semantics.
- Copying page geometry avoids imposing a fixed paper size on mixed documents.
- Applying the overlay before bookmark reconstruction keeps the final outline
  tree based on the final assembled page objects.

## Known limits

The overlay still uses Helvetica with WinAnsi encoding, so Unicode font
embedding and non-ASCII filename fidelity remain open. Placement now asks
`MuPDF` for bounded structured-text boxes and selects a quiet bottom or top
band when one is available. If the optional text extractor is unavailable, the
adapter falls back to the original deterministic geometry-only position. This
is a bounded collision-avoidance policy, not a claim of full semantic layout
under forms, annotations, images or rotated writing modes.

Configurable typography, embedded Unicode fonts and a visual golden baseline
remain follow-up work before MERGE-007 can become Verified.
